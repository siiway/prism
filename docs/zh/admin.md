# 管理员指南

管理面板位于 `/admin`，仅对管理员可见。第一个管理员账号在首次初始化时创建。之后可通过 **管理 → 用户 → 管理 → 角色** 提升其他人为管理员。

面板首页是概览：需要处理的事项（未配置邮件、未启用验证码、密钥尚未加密）、使用情况统计、最近活动和关键设置。在任意页面按 Ctrl/⌘ K 可按名称搜索页面、设置和数据。

## 设置

设置分为多个分区，每个分区是管理侧栏中的独立页面。所有更改立即生效，无需重新部署。各项设置对应的配置键见 [配置](configuration.md)。

### 常规

站点名称、描述和图标，以及可选的**安全联系方式**和**安全策略 URL**。设置联系方式后，Prism 会提供 `/.well-known/security.txt`。

### 注册

- **注册模式** — 开放、仅限邀请或关闭。
- **邮箱验证** — 开启后，新用户必须验证邮箱才能登录。

### 登录与安全

- **会话、访问令牌和刷新令牌的有效期。**
- **Sudo 模式** — 用户完成一次 2FA 加强验证后，同一应用在该时长内的后续挑战可跳过 TOTP/Passkey 提示。`0` 表示禁用。详见 [OAuth → 加强 2FA](oauth.md#加强-2fa)。
- **2FA 加强验证需要验证码** — 每次加强验证都必须通过验证码。
- **登录限流** — 每 IP 的登录尝试、每个邮箱或用户名的尝试，以及 TOTP 提交的额度和时间窗口。
- **IPv6 限流前缀长度** — 限流时 IPv6 地址按多少位前缀归为同一桶（默认 `/64`）。

### 验证码

选择一个**默认提供商**，并可选择若干**备用提供商**，在默认方式失败或过慢时访客可以切换。将默认设为**无**即关闭验证码。

| 提供商               | 说明                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| Cloudflare Turnstile | 需要站点密钥 + 密钥，有免费套餐                                      |
| hCaptcha             | 需要站点密钥 + 密钥                                                  |
| reCAPTCHA v3         | 需要站点密钥 + 密钥，无感验证                                        |
| 极验 v4              | 需要 CAPTCHA ID + 密钥。**故障放行**决定极验故障时是否放行，默认关闭 |
| Cap                  | 自建工作量证明，可内嵌在 Prism 中或使用外部服务器                    |

使用 Turnstile 时，**验证端点**设置用于选择全球主机还是中国大陆主机。选择「始终全球」以外的任何模式，都需要再填写一组**中国大陆 站点密钥** 和**密钥**，它们来自以 `region: "china"` 创建的组件，需要 Cloudflare China Network 权限。中国大陆 站点密钥 留空时，访客只会得到全球组件。

### 邮件

**发送** — 选择提供商（Resend、Mailchannels 或 SMTP）和发件地址，可用**发送测试邮件**检查是否正常。

**接收** — 让用户可以通过向 Prism 发邮件来验证邮箱：

- **验证方式** — `link`、`send` 或 `both`。
- **接收方式** — Cloudflare Email Workers（用户发送到 `verify-<code>@<host>`）、IMAP（Prism 每 6 小时轮询邮箱，用户把验证码作为主题发送），或无。

### 公开资料

- **用户可发布公开资料** — 总开关。关闭后所有公开资料页面都返回 404。
- 用户和团队资料各字段的**默认值**。默认值不会覆盖用户或团队的显式选择。详见 [公开资料](public-profile.md)。

### 用户与团队

- **团队加入门槛** — 要求所有团队都启用 2FA 或已验证邮箱。开启后会立即对现有成员生效，未满足的成员将无法进行团队操作，请先通知成员。
- **子团队** — 允许或禁止团队嵌套，设置最大深度（1–20，默认 5），并选择成员资格和已验证域名是否向子团队继承。详见 [团队 → 子团队](teams.md#子团队)。

### 通知

选择用于推送聊天通知的 Telegram 和 Discord OAuth 来源（以及 Discord bot token）。留空即关闭该渠道。详见 [通知](notifications.md)。

### 外观与法律条款

- **主题色**和**自定义 CSS**，应用于每个页面。
- **页脚署名**：在每个页面底部显示“由 Prism 驱动”及源代码链接。默认显示，设为隐藏即可移除。
- **隐私政策**和**服务条款**，使用 Markdown 编写，发布于 `/privacy` 和 `/terms` 并在页脚提供链接。留空则隐藏。每份上限 256 KiB。

### 域名与诊断

已验证域名的重新核验频率（默认 30 天），以及登录失败记录的保留时间。

### 危险区域

位于 **维护** 分组下。每个工具都可以安全地重复执行。

- **迁移密钥到 Secret Store** 和 **哈希并加密已存储的令牌** — 绑定 [`SECRETS_KEY`](configuration.md#secrets-key-配置) 后，加密或哈希已有密钥。
- **站点重置** — 清空并重新初始化。需要可用的邮件提供商，并在 `wrangler.jsonc` 中设置 `ENABLE_RESET = "true"`，否则按钮不显示。
- **登出所有人** — 删除所有会话。默认保留你自己的会话。OAuth 令牌不受影响。

**维护任务**可按需运行计划任务（域名重新验证、邮箱轮询、清理等），无需等待每六小时一次的调度。

## OAuth 来源

**管理 → OAuth 来源** 用于配置社交登录。每个来源是一个独立连接，有自己的 slug 和凭据，因此可以同时存在两个 GitHub 应用，或 Keycloak 与 Google 并存。

| 字段               | 说明                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------ |
| Slug               | 唯一键，用于回调 URL                                                                 |
| 提供商             | GitHub、Google、Microsoft、Discord、Telegram、X、Cloudflare、通用 OIDC、通用 OAuth 2 |
| 显示名称           | 登录按钮上的标签                                                                     |
| Client ID / Secret | 来自提供商                                                                           |
| 受信任             | 开启（默认）时，通过该来源登录会跳过邮箱验证                                         |
| 启用               | 显示或隐藏该来源，不会删除数据                                                       |

请在提供商处注册这个回调 URL：

```text
https://<your-prism-domain>/api/connections/<slug>/callback
```

通用 OIDC 来源还需要 **Issuer URL**（点击**自动发现**可自动填入各端点）和可选的**权限范围（Scopes）**。通用 OAuth 2 来源需要手动填写三个端点 URL。各提供商的配置步骤见[社交登录配置](social-login.md)。

## 邀请

仅限邀请模式下，**管理 → 邀请** 可创建、编辑、禁用和撤销邀请链接。每个邀请可限定邮箱、使用次数和有效期。被禁用的邀请在重新启用前无法注册。

## 用户

用户列表支持搜索和排序。用复选框选中账号后，可一次对最多 50 个账号执行启用、停用或删除，你自己的账号会被跳过。

| 操作           | 效果                               |
| -------------- | ---------------------------------- |
| 更改角色       | 在用户和管理员之间切换             |
| 停用           | 禁止登录；已有令牌在过期前仍然有效 |
| 标记邮箱已验证 | 无需发送邮件即可验证               |
| 删除           | 永久删除用户、其应用和全部数据     |

列在 `LOCKDOWN_USERS` 中的用户名不能被删除。参见 [配置 → Wrangler 绑定与变量](configuration.md#wrangler-绑定与变量)。

**管理 → 用户 → 管理** 会打开单个账号的完整页面：

- **概览** — 修改用户名、邮箱和显示名称；设置或清除密码；重置全部 2FA 或移除单个因子；验证、提升或移除邮箱地址。设置密码不会通知用户，请另行告知。
- **访问** — 个人访问令牌、已关联的提供商、GPG 密钥和已授权的应用，每项都可撤销。**撤销所有授权**会切断该账号对所有应用的授权。令牌值不会显示。
- **资源** — 个人域名、团队，以及通知路由（用户反映收不到通知时可重置）。
- **审计** — 账号自身做过的事，以及管理员对它做过的事。

这里的管理员操作会记录在用户自己的审计日志中，并标记为站点管理员操作。不提供以他人身份登录的功能。

## 应用

**管理 → 应用** 列出所有 OAuth 应用及其所有者和状态。

| 操作         | 效果                                                     |
| ------------ | -------------------------------------------------------- |
| 验证         | 在授权页面显示已验证标记                                 |
| 停用         | 禁止新的授权；已有令牌继续有效                           |
| 撤销所有访问 | 删除该应用的全部令牌、授权码和授权记录（可同时停用应用） |
| 转移         | 把应用转给任意用户或团队，client ID 和密钥不变           |

## 团队

**管理 → 团队** 列出所有团队及其所有者和成员数。

| 操作     | 效果                                     |
| -------- | ---------------------------------------- |
| 管理     | 以所有者权限打开团队页面，无需加入       |
| 添加成员 | 以不超过共同所有者的任意角色添加任何账号 |
| 创建     | 创建团队并指定所有者                     |
| 解散     | 移除团队，其应用转给团队所有者           |

列在 `LOCKDOWN_TEAMS` 中的团队名不能被解散。若要禁止普通用户创建团队，请开启 `disable_user_create_team`（见 [配置](configuration.md#通用)）。

站点管理员对每个团队都拥有所有者级权限。管理员可以添加任何人、修改或移除任何成员（包括所有者）以及转移所有权；添加人员时团队的加入门槛会被豁免。这些操作会在团队审计日志和平台日志中标记为站点管理员操作。以站点身份操作时，团队页面会显示横幅，**切换为普通视图**则改为以你自己的成员身份操作。移除或降级所有者可能让团队暂时没有所有者，这是允许的，之后在团队页面提升某人即可。

### 邀请链接注册

在团队的**审核**标签页，**允许邀请注册**让该团队的管理员可以创建能够创建新账号的邀请链接。**允许这些账号转为完整账号**会覆盖该团队的站点默认值。注册关闭时，任何团队的邀请都不能创建账号。

要解散创建过账号的团队，请使用其审核标签页上的分阶段流程。第一阶段停用它创建的所有账号；第二阶段在宽限期后删除，其间可以取消。以自己账号加入的成员以及已转为完整账号的人不受影响。参见 [团队 → 受限账号](teams.md#受限账号)。

**管理 → 邀请 → 团队邀请** 列出实例上所有未失效的团队邀请。撤销链接会立即使其失效，已通过它创建的账号保留。

## 域名

**管理 → 域名** 列出所有个人和团队域名。**强制验证**会在不检查 DNS 的情况下把域名标记为已验证（用于 worker 无法访问的域名，例如内部顶级域），审计记录会标明这是管理员覆盖。也可以**撤销验证**或**删除**。

## 作用域授权

**管理 → 作用域授权** 列出应用持有的高权限 OAuth 授权：`site:*`（跨整个实例操作）和 `team:<id>:*`（在某个团队内操作）。打开一项可以看到批准人、允许的内容以及有多少活跃令牌携带它。**撤销此授权**会移除这些 scope，以及携带它们的令牌和授权码，应用保留其他已获批准的内容。

## 公告

**管理 → 公告** 用于发布显示在产品内的公告：计划内停机、政策变更、安全通告。

| 字段          | 作用                                                                       |
| ------------- | -------------------------------------------------------------------------- |
| 级别          | info、warning 或 critical                                                  |
| 受众          | 所有人（包括登录页上的未登录访客）、已登录用户、仅管理员，或某个团队的成员 |
| 开始/结束时间 | 公告出现和消失的时间                                                       |
| 可关闭        | 对必须保持可见的内容（如进行中的事故）关闭                                 |
| 置顶          | 排在同级别的其他公告之上                                                   |

公告使用 Markdown，发布前是草稿，因此半成品不会出现。读者关闭公告只对自己生效；编辑不会让它重新出现，**重新展示**才会。「取消发布」可撤下公告并保留为草稿。

如果部署新增了公告表，但还没有运行 `wrangler d1 migrations apply`，公告板会显示为空，**管理 → 公告** 会提示这一点。

## 数据库与键值浏览器

**管理 → 数据库** 提供对 D1（表浏览器、行编辑器、SQL 控制台）和 KV 命名空间的直接访问。它**默认关闭**，需在 `wrangler.jsonc` 中用 `D1_CONSOLE` 变量开启：

| `D1_CONSOLE`                 | 效果                   |
| ---------------------------- | ---------------------- |
| 未设置、`off` 或无法识别的值 | 该标签页不存在（默认） |
| `read-only`                  | 仅可浏览和 `SELECT`    |
| `full`                       | 可读写                 |

`KV_CONSOLE` 以同样方式控制键值浏览器，未设置时跟随 `D1_CONSOLE`。

注意事项：

- SQL 控制台中的写入需要明确选择**读写**模式并经过确认。每条语句都会记录在平台审计日志中。
- 审计表在任何设置下都只能读取，不能从这里写入。
- 签名密钥永远不会显示或可编辑。删除一个密钥即轮换它，会让所有人登出。
- 结果集上限为 500 行。

## 审计日志

**管理 → 审计日志** 是平台级日志，记录所有管理操作。用户和团队各有自己的范围日志。筛选、导出和 Webhook 见 [审计日志](audit-logs.md)。

**管理 → 登录错误** 列出失败的登录尝试，包含错误码、标识符和 IP。
